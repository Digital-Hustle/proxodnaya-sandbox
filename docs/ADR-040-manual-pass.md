# ADR-040 · Ручной пропуск с подтверждением, плавные переходы, единый фон

Статус: принято · 2026-10-08

## Контекст

Терминал иногда не может решить сам: нет связи с сервером, сел телефон, человек без пропуска. Тогда пропускает охранник поста или старший по должности. Такой проход нельзя запретить, иначе у турникета встанет смена. Но и оставлять его без контроля нельзя: ручной пропуск — самый удобный путь для злоупотреблений.

## Решение: правило двух людей

1. **Решение действует сразу.** Охранник пропускает человека, в журнал пишется запись `MANUAL` с причиной и именем того, кто пропустил (`Attempt.guard`).
2. **Запись ждёт подтверждения.** Пока второй человек её не проверил, в журнале у неё отметка «ждёт подтверждения», а в шапке журнала — кнопка «На проверке · N» с фильтром только таких записей.
3. **Проверяет другой человек.** Право «Проверка ручных» есть у администратора и службы безопасности, у охранника его нет: никто не проверяет сам себя. Проверяющий видит сотрудника, время, проходную, кто пропустил и причину.
4. **Подтвердить или оспорить.** Оспорить можно только с комментарием, и это открывает разбор инцидента. Результат проверки (`Attempt.review`: статус, кто, когда, комментарий) записывается один раз и потом не меняется.

В демо-стенде это работает так: ручной пропуск из демо-пульта или с экрана «Нет связи» → «Журнал» → отметка у записи → «Подтвердить» или «Оспорить».

## Что нужно в боевом развёртывании

- **Персональные учётные данные охранника** (карта или личный PIN плюс табельный номер) вместо общего PIN поста. В журнале — конкретный человек, а не «Охранник поста».
- **Причина обязательна** и выбирается из справочника, плюс свободный комментарий.
- **Снимок с камеры киоска** прикладывается к записи, чтобы проверяющий сверил лицо.
- **Без связи:** записи копятся в локальной очереди киоска, подписываются ключом терминала (выдаётся при привязке) и уходят на сервер при восстановлении связи. Сервер отклоняет записи с неверной подписью или временем.
- **Срок проверки:** 24 часа. Непроверенные записи эскалируются начальнику службы безопасности и видны на дашборде.
- **Старший по должности** может пропустить сам, но его решение тоже логируется под его учётной записью и тоже проверяется другим человеком. Исключений по званию нет.
- **Оспоренный пропуск** создаёт инцидент: уведомление службе безопасности, ссылка на видеозапись, отметка в карточке сотрудника.
- **Аудит:** журнал только дописывается, правки и удаления записей запрещены на уровне хранилища.

## Логика терминала: одна для всех или своя у каждого

В «Настройках → Логика терминала» выбирается, где она задаётся:

- **Одна для всех терминалов** (по умолчанию): режим прохода и поведение без связи задаются в настройках и сразу действуют на всех киосках. В карточке терминала выбор не показывается, только подсказка со ссылкой на настройки.
- **Своя у каждого терминала**: настройки становятся значением по умолчанию, а в «Терминалах» каждому киоску можно задать свой режим (`Kiosk.mode`) и поведение без связи (`Kiosk.offlinePolicy`). Значения на киосках сохраняются и при обратном переключении: они просто перестают действовать.

Какая логика действует, определяется в одном месте: `terminalModeOf` / `offlinePolicyOf`.

## Переходы и фон

- Фон (Aurora) рисуется один раз в корневом layout роутера и не пересоздаётся при переходах. Интенсивность одинаковая на главной, в кабинете, пропуске и админке (`PAGE_AURORA`), на киоске чуть ярче (`KIOSK_AURORA`) для экрана на расстоянии. Цвета берутся из токенов темы, поэтому светлая и тёмная тема ведут себя одинаково.
- Переход между разделами (главная, киоск, пропуск, кабинет, админка) — плавная смена прозрачности через `AnimatePresence mode="wait"` с `tween.exit` / `tween.base`. Уходящий экран «заморожен», чтобы не было мигания содержимым следующего. Внутри раздела страницы меняются через `pageIn`.
- Навигация админки прокручивается по горизонтали колесом мыши и перетаскиванием с зажатой кнопкой; активная вкладка сама прокручивается в зону видимости.
