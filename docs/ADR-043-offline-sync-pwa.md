# ADR-043. Подписанный журнал без связи, PWA и новый знак сканера

Статус: принято. Дополняет ADR-042.

## Контекст

В ADR-042 терминал научился пропускать без связи, но очередь уходила на сервер как есть.
Любой, кто получит доступ к хранилищу терминала, мог бы:

- дописать проход, которого не было;
- поменять время или человека;
- тихо удалить неудобную запись.

Кроме того, приложения открывались только при живой сети: без неё браузер не мог загрузить страницу, хотя QR пропуска подписывается на самом телефоне.

## Решение

### 1. Журнал терминала — цепочка хэшей

Каждое решение без связи получает:

- `seq` — номер записи на этом терминале;
- `prev` — хэш предыдущей записи (первая ссылается на `genesis`);
- `hash` — SHA-256 от канонического JSON записи (ключи по алфавиту) вместе с `prev`;
- `proof` — исходная строка QR с подписью телефона сотрудника.

Голова цепочки (`proxodnaya.kiosk.chain`) хранится отдельно от кэша и не сбрасывается кнопкой «Сбросить снимок допусков».

### 2. Пакеты, подписанные ключом терминала

- При первом запуске терминал создаёт ключ ECDSA P-256. Закрытая часть неизвлекаемая и лежит в IndexedDB (слот `kiosk`).
- Открытый ключ уходит на сервер с пульсом `kioskHello` и запоминается один раз. В продукте — при сопряжении.
- Очередь уходит пакетами до 50 записей: `{ v, kioskId, nonce, sentAt, events }`. Пакет подписывается целиком.
- Сервер отвечает списком принятых записей. Только их терминал убирает из очереди. Остальное уйдёт при следующей попытке (раз в минуту и сразу при появлении связи).
- Повторная отправка безопасна: записи идемпотентны по `id`.

### 3. Что проверяет сервер

| Проверка | Если не сошлось |
|---|---|
| Подпись пакета ключом терминала | Пакет отклоняется целиком и остаётся в очереди. Ошибка видна в сервисной панели |
| Хэш записи | Запись отбрасывается как изменённая, счётчик отклонённых виден в сервисной панели |
| `prev` и `seq` продолжают принятую цепочку | Конфликт «разрыв журнала терминала» — записи пропали или переставлены |
| Подпись сотрудника в `proof` ключом его телефона | Конфликт «подпись сотрудника не подтверждена» |
| QR совпадает с записью (сотрудник, телефон, окно) | Конфликт «QR не совпадает с записью» |
| Время прохода внутри окна QR ± допуск часов | Конфликт «время прохода не совпадает с временем QR» |
| Отвязка телефона, повтор кода, блокировка (ADR-042) | Конфликт, как раньше |

Итог: терминал не может «провести» человека, которого не было у турникета, — у него нет закрытого ключа телефона.
Сдвинуть время тоже нельзя: оно привязано к 30-секундному окну подписанного QR.
Удаление записи видно по разрыву цепочки.

### 4. Установка как приложение (PWA)

- Три манифеста с разными `id`: пропуск (`manifest.webmanifest`), терминал (`manifest-kiosk.webmanifest`), админка (`manifest-admin.webmanifest`). Нужный подставляется по маршруту.
- Иконки PNG 192/512 и maskable, иконка для iOS.
- Service worker (`scripts/sw.js`) собирается плагином `scripts/vite-pwa.ts`: при установке кладёт в кэш оболочку и все чанки. Страница — сначала сеть, без сети — из кэша. Шрифты — из кэша с фоновым обновлением.
- Кнопка «Установить» появляется, когда браузер готов поставить приложение: в шапке пропуска, в шапке админки и в сервисной панели терминала.

### 5. Пропуск сотрудника без сети

- QR подписывается на телефоне и обновляется каждые 30 секунд без сети — так было и раньше.
- Теперь приложение открывается без сети из кэша, а карточка пропуска (ФИО, должность, подрядчик) хранится на телефоне (`proxodnaya.worker.card`).

### 6. Знак сканера

Один путь из четырёх кубических сегментов «лево → низ → право → верх» и видимая доля `pathLength`:

1. Линия сканирует рамку и встаёт в центр.
2. Нижняя часть выгибается в полуокружность.
3. Дуга дорастает против часовой стрелки до кольца.
4. Внутри белым штрихом той же толщины пишется галочка, перетекает в крестик и схлопывается в точку. Это часть заставки, а не вердикт: цвет белый.
5. Кольцо продолжает движение против часовой стрелки, раскрывается сверху и снова ложится в линию.

Без свечений и CSS-анимаций, учитывается reduced motion.

Ещё: новый или отвязанный телефон сразу попадает в снимок допусков, не дожидаясь минутного обновления. Демо-QR, созданный при связи, работает и без неё.

## Риски

- Ключ терминала запоминается при первом контакте. В продукте его нужно регистрировать при сопряжении по коду из админки.
- Украденный терминал с ключом может подписать пакет, но не может подделать подпись сотрудника. Худшее — повтор реального прохода, который ловится одноразовостью кода.
- Кэш service worker обновляется при следующем открытии со связью. Свежая версия применяется после перезагрузки.
