# ADR-046. Коды терминалов, вход по почте, эталон лица, пропуск v4, график по дням, стриминг помощника

Статус: принято · Связано: ADR-038, ADR-040, ADR-041, ADR-042, ADR-045 · Контракт для бэкенда — [BACKEND-CONTRACT.md](BACKEND-CONTRACT.md)

## Контекст
- Сервисный код 2580 и PIN охранника 0000 были зашиты в код: сменить их было нельзя, а любой, кто видел стенд, знал оба.
- На iPhone кнопка «Установить» ничего не делала: Safari не шлёт `beforeinstallprompt`.
- Экран пропуска v3.4 всё равно выглядел слабее лендинга.
- В админке колонки выбора времени (новый сотрудник, график) при прокрутке прыгали обратно к выбранному значению.
- График задавался только одним временем на все выбранные дни.
- Ответ помощника появлялся целиком после паузы.
- Кабинет открывался без входа, роль переключалась в шапке.
- Не было решено, откуда у нового сотрудника берётся эталон лица.

## Решение
1. **Коды терминалов.** Админка → Терминалы → «Коды на терминалах»: сервисный (ADMIN, SECURITY_OFFICER, INSTALLER) и охранника (ADMIN, SECURITY_OFFICER). 4–6 цифр, слабые отклоняются (`weakTerminalCode`: одинаковые, подряд, заводские, год). Сервер хранит только PBKDF2-SHA256 (120 000 итераций, соль 16 байт) — `shared/lib/terminalCode.ts`. Хэш раздаётся в снимке допусков (`OfflineSnapshot.codes`), поэтому код охранника проверяется на киоске и без связи (`widgets/kiosk-terminal/model/useTerminalCode`). 5 ошибок → блокировка ввода на 60 с (переживает перезагрузку). Пока коды не заданы, действуют заводские и подсвечиваются как «заводской». Смена — в журнале доступа (`CODE`).
2. **Установка на iPhone/Mac/Firefox.** `manualInstall()` определяет платформу (`ios`, `ios-other` — Chrome/Firefox/Edge/Яндекс на iOS, `mac-safari`, `android` — Firefox/Samsung). Если системного запроса нет, `InstallButton` открывает инструкцию из трёх шагов («Поделиться» → «На экран „Домой“» → «Добавить»).
3. **Пропуск v4 — по мотивам лендинга.** Приветствие в `PageHeader`; карточка `rounded-2xl bg-brand-deep` с бликом `bg-sheen`: знак, «Пропуск на объект» + объект (ссылка в профиль), пилюля зоны; QR на белой плашке, белая полоса отсчёта (`PassQr tone="brand"`). Ниже — плитки дня крупными цифрами Display (`сегодня`, `время входа`, смена с полосой и «До конца…»), блок про одноразовый код.
4. **Выбор времени.** Колонка (`TimeCol`) центрирует выбранное один раз при открытии и только своим `scrollTop` (без `scrollIntoView`). `Popover` больше не перерисовывается от прокрутки внутри своей панели — это и сбрасывало позицию.
5. **График по дням.** `features/plan-week`: шаблоны, режим «Одинаково все дни» (дни + одно время) и «По дням» (у каждого дня переключатель и своё время, кнопка «такое же время на все рабочие дни»). `assignSchedule({ days: [{ weekday, start, end }] })`. Используется в диалоге графика и в мастере нового сотрудника (график на 14 дней).
6. **Стриминг помощника.** `assistant.ask(q, history, { onEvent, signal })`: события `tool` (вызов инструмента) и `delta` (кусок текста). С моделью — SSE OpenAI-совместимого API (`stream: true`, сборка `tool_calls` по кускам); без модели правила отдают тот же поток. `StreamReply`: шаги инструментов (активный — с бегущим бликом, пройденные — с галочкой), куски текста проявляются из размытия, мигающий курсор; кнопка «Стоп», «Ответ остановлен», лента прилипает к низу, если пользователь не отмотал.
7. **Вход в кабинет по почте.** `/login`: адрес → 6 цифр из письма → сессия 12 ч. Без пароля. Код живёт 10 мин, 5 попыток, повтор через 45 с, ответ одинаковый для любого адреса. `CodeInput` — ячейки поверх одного `input autocomplete="one-time-code"` (вставка и автоподстановка работают), цифра выпрыгивает, ячейка заливается, при проверке — волна, при ошибке — отскок пружиной, при успехе — фирменная заливка и галочка; отправка сама, когда введены все цифры. Кабинет без живой сессии уводит на `/login?next=…`; отключённый пользователь выбрасывается сразу. Переключатель ролей в шапке заменён на «Учётная запись» (Войти другим / Выйти). В песочнице письмо заменено уведомлением с кодом.
8. **Эталон лица.** Основной путь — **снимок при оформлении (HR)**: он сразу эталон. Если фото нет — сотрудник после активации делает «Лицо для прохода» на своём телефоне, как Face ID: камера в круге, поворот головы (живость по кадрам), снимок; запрос подписан ключом телефона (`face|workerId|deviceId|at`), сервер проверяет подпись и живость. Такой эталон **не включается сам**: служба безопасности сверяет его с документом в карточке сотрудника (Подтвердить / Отклонить). До подтверждения на «QR + лицо» киоск отвечает `FACE_NOT_ENROLLED`, пропускает охранник. В продукте возможен и третий источник — снимок на терминале при охраннике (`source: KIOSK`).

## Почему так
- Эталон только с телефона без проверки человеком позволяет подставить чужое лицо: телефон сотрудника и сам сотрудник — не одно и то же. Подпись ключом устройства доказывает, с какого телефона пришло, но не кто на снимке. Поэтому — HR при оформлении, а селфи — только с подтверждением.
- Коды как хэш, а не открытый текст: снимок допусков лежит на терминале, его можно вытащить.
- Одинаковый ответ на запрос кода не даёт перебирать адреса.

## Последствия
- `OfflineSnapshot.codes`, `Db.terminalCodes / loginCodes / adminSessions`, `Worker.face`, `ReasonCode FACE_NOT_ENROLLED`, `AccessEvent.action CODE|LOGIN|LOGOUT` — аддитивно, старые базы работают (нет `face` = эталон есть).
- Контракт для бэкенда и предложения в `docs/API.md` основного репо — [BACKEND-CONTRACT.md](BACKEND-CONTRACT.md).
- `Progress` — тоже `translateX` (как `CountdownBar`, ADR-045), добавлен тон `white`; `CountdownBar` принимает `fillClassName`.
