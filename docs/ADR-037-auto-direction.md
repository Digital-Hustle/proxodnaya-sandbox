# ADR-037. Автоматическое определение направления прохода

Статус: принято · октябрь 2026

## Контекст
В первой версии киоска охранник или сотрудник выбирал «Вход / Выход» переключателем перед сканированием. Это лишний шаг у турникета, источник ошибок (забыли переключить — в журнале «вход» вместо «выхода») и поле для злоупотреблений. Сотрудник должен только предъявить QR-пропуск.

## Решение
Направление определяет сервер при обработке скана (`resolveDirection` в `src/shared/api/mock/server.ts`). Киоск и телефон не передают и не показывают выбор направления.

Порядок определения:
1. **Фиксированный режим КПП.** У проходной есть `mode`: `AUTO` (по умолчанию), `IN` или `OUT`. Для отдельных турникетов входа и выхода направление берётся из режима.
2. **Состояние присутствия.** Для `AUTO`: если у сотрудника есть открытый интервал присутствия (вход без выхода) моложе `presenceTtlHours` (16 ч) — это **выход**, иначе — **вход**.
3. **Защита от повторного скана.** Если успешный проход (`ALLOW` / `MANUAL`) этого сотрудника был меньше `repeatScanCooldownSec` (30 с) назад — отказ `REPEAT_SCAN`. Без этого сотрудник, задержавший телефон у камеры, получил бы пару «вход → выход» за секунду.

```
          скан (нет открытого интервала)
  ВНЕ ───────────────────────────────▶ ВНУТРИ
   ▲                                     │
   │  скан (интервал открыт < TTL)       │
   └─────────────────────────────────────┘
  интервал старше TTL → «забытый выход», следующий скан = вход
```

Ручной пропуск охранником (`kioskManual`) использует ту же логику — указываются только сотрудник и причина.

## Коды
| Код | Когда |
|---|---|
| `REPEAT_SCAN` | повторное предъявление в пределах `repeatScanCooldownSec` |
| `ALREADY_INSIDE` | только для КПП в режиме `IN`: сотрудник уже внутри |
| `NOT_INSIDE` | только для КПП в режиме `OUT`: открытого интервала нет |

Направление до идентификации (битый или поддельный QR) — режим КПП, для `AUTO` — `IN`; на решение оно не влияет.

## Настройки
«Настройки → Определение направления»: интервал защиты от повтора, срок незакрытого присутствия и режим каждой проходной.

## Последствия
- Киоск — один экран «Покажите QR-пропуск»; шаг выбора исчез.
- Забытый выход не блокирует сотрудника: через TTL интервал считается закрытым, следующий скан — вход. Такие интервалы видны в аналитике как незакрытые.
- Направление в журнале всегда вычислено сервером и одинаково для киоска, ручного пропуска и отчётов.
- Для КПП с раздельными турникетами нужно один раз задать режим, иначе вход через турникет «выхода» будет записан по состоянию присутствия.
