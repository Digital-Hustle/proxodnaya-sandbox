# Проходная · песочница

Черновой стенд фронтенда кейса «Проходная» (хакатон «СберБизнесВайб»). **Весь бэкенд — моки в браузере**, данные лежат в `localStorage`, вкладки синхронизируются через `BroadcastChannel`. Это не продуктовый код: продукт пишется в основном репозитории `Digital-Hustle/sber-hack` во время хакатона.

Открыть: **https://digital-hustle.github.io/proxodnaya-sandbox/**

## Что можно потрогать
| Зона | Адрес | Что есть |
|---|---|---|
| Киоск | `#/kiosk` | камера + скан QR (`@zxing/browser`), челлендж живости, экран вердикта, **вход или выход определяется автоматически** ([ADR-037](docs/ADR-037-auto-direction.md)), демо-пульт: предъявление пропуска любого сотрудника с прогнозом направления, повторный и просроченный QR, подделка подписи, другой человек в кадре, фото вместо лица, ручной пропуск |
| Телефон | `#/worker` | активация по коду (демо: `PETR01`, `ANNA03`, `DENIS5`) или по ссылке-инвайту; ключ ECDSA P-256 неизвлекаемый, в IndexedDB; QR каждые 30 с, без сети; история и смены |
| Админка | `#/admin` | обстановка, люди, заведение за 2 минуты (данные → фото с вебкамеры → смена → инвайт-QR), карточка (блок, отвязка телефона, допуск), журнал с фильтрами в URL и CSV, смены (план/факт), аналитика с «как посчитано», помощник, настройки порогов |

Сценарий на двух устройствах: админка на ноутбуке → новый сотрудник → телефон сканирует инвайт → на ноутбуке открыть киоск → показать QR с телефона в камеру.

## Как устроено
- Vite + React 19 + TypeScript strict + Tailwind 4 + motion (+ ogl для живого фона), FSD; HashRouter — работает на Pages без fallback.
- Стиль только из `src/shared/config/tokens.ts` → `npm run gen:tokens` → `src/app/styles/theme.css` (ADR-033 основного репо). Проверка архитектуры и литералов — `node scripts/fsd-check.mjs src`.
- «Сервер» — `src/shared/api/mock/server.ts`: решение о проходе принимается там, UI показывает то, что вернулось (как Д2 в продукте). Коды и тексты отказов — из `docs/API.md` основного репо.

### Направление прохода
Киоск не спрашивает «вход или выход» — сотрудник только показывает QR. Сервер решает сам: КПП с фиксированным режимом (`IN`/`OUT`) → его направление; иначе открытый интервал присутствия моложе 16 ч → выход, нет — вход. Повторный скан в течение 30 с отклоняется кодом `REPEAT_SCAN`. Параметры — в «Настройках», подробности — [ADR-037](docs/ADR-037-auto-direction.md).

### Логика терминала и работа без связи
Логика выбирается в «Настройках» (для всех терминалов) или в «Терминалах» (для отдельного киоска). Решение всегда принимает сервер.
- **QR + лицо** (по умолчанию): QR → челлендж живости → сверка лица 1:1 (Д2).
- **Сначала лицо**: узнавание по базе со строгим порогом и живостью; не узнали — QR как запасной путь.
- **Без связи** автоматического пропуска нет: пропускает охранник (PIN + причина, запись MANUAL, FR-70) или проход закрыт. «Офлайн по одному QR» — это клиентское решение без лица и с повторно предъявляемым кодом, то есть критерии снятия Д10, поэтому его нет.
- Новый киоск показывает код сопряжения и никого не пропускает, пока его не привяжут в «Терминалах». Сервисная панель: удержать логотип, код 2580; PIN охранника в демо — 0000.

Подробно, вместе с ролями: [ADR-038](docs/ADR-038-terminal-modes.md).

### Большие объекты

Списки не грузятся целиком: Люди, Журнал и Смены читают данные страницами по мере прокрутки, а поиск и фильтры работают на стороне сервера. Зон и КПП может быть сколько угодно. Чтобы проверить, откройте Настройки → Демо-режим → «Добавить 400 человек и 5 зон». Контракт API и пограничные случаи описаны в [ADR-039](docs/ADR-039-data-scale.md).

Ручной пропуск действует сразу, но ждёт подтверждения вторым человеком в журнале; логика терминала задаётся одна для всех или своя у каждого киоска. Подробно и требования к боевому развёртыванию — [ADR-040](docs/ADR-040-manual-pass.md).
Главный администратор выдаёт и меняет роли, приглашает и отключает людей в разделе «Доступ»; всё пишется в журнал. Терминал — без рамки, на общем фоне. Подробно — [ADR-041](docs/ADR-041-access.md).

Режим «Только QR» и автономная проверка QR без связи: терминал сам проверяет подпись по снимку допусков, проходы синхронизируются, когда связь вернётся. Подробно — [ADR-042](docs/ADR-042-qr-only-offline.md).

Подписанный журнал проходов без связи (цепочка хэшей, пакеты с подписью терминала, перепроверка подписи сотрудника на сервере), установка как приложение (PWA) для пропуска, терминала и админки, работа без сети, новый знак сканера. Подробно — [ADR-043](docs/ADR-043-offline-sync-pwa.md).

Интерфейс сотрудника в дизайне кабинета: новая карточка пропуска, один QR на все объекты, постраничная история, календарь смен. Подробно — [ADR-044](docs/ADR-044-worker-app.md).
Карточка пропуска v3.3, профиль с выходом, плавная перестройка QR, фиксы iOS (полоса таймера, дрожание шапки) — [ADR-045](docs/ADR-045-pass-profile-ios.md).

## Упрощения песочницы (в продукте иначе)
- Нет общего сервера, поэтому публичный ключ телефона едет внутри QR, а киоск привязывает его при первом скане. В продукте ключ регистрируется при активации, и чужой ключ = `DEVICE_UNKNOWN`.
- Ссылка-инвайт несёт карточку сотрудника, чтобы телефон без сервера знал, кого привязывает.
- Биометрии нет: живость — по движению в кадре (фото без движения не пройдёт), совпадение лица — переключатель в демо-пульте.
- История на телефоне видна, только если киоск открыт в том же браузере.

## Помощник
Без настройки отвечает правилами по данным (кто на объекте, опоздания, отказы, часы, конкретный сотрудник). Кнопка «Модель» подключает любой OpenAI-совместимый API с tool calling (DeepSeek, Qwen, GLM, локальный Ollama): модель вызывает те же инструменты, цифры берутся только из них. Ключ хранится только в `localStorage` вашего браузера; для общего стенда нужен прокси на сервере, чтобы ключ не попадал в браузер.
