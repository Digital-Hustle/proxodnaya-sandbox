# Проходная · песочница

Черновой стенд фронтенда кейса «Проходная» (хакатон «СберБизнесВайб»). **Весь бэкенд — моки в браузере**, данные лежат в `localStorage`, вкладки синхронизируются через `BroadcastChannel`. Это не продуктовый код: продукт пишется в основном репозитории `Digital-Hustle/sber-hack` во время хакатона.

Открыть: **https://digital-hustle.github.io/proxodnaya-sandbox/**

## Что можно потрогать
| Зона | Адрес | Что есть |
|---|---|---|
| Киоск | `#/kiosk` | камера + скан QR (`@zxing/browser`), челлендж живости, экран вердикта, вход/выход, демо-пульт: виртуальный телефон, повтор QR, старый скриншот, подделка подписи, чужое лицо, фото вместо человека, ручной проход |
| Телефон | `#/worker` | активация по коду (демо: `PETR01`, `ANNA03`, `DENIS5`) или по ссылке-инвайту; ключ ECDSA P-256 неизвлекаемый, в IndexedDB; QR каждые 30 с, без сети; история и смены |
| Админка | `#/admin` | обстановка, люди, заведение за 2 минуты (данные → фото с вебкамеры → смена → инвайт-QR), карточка (блок, отвязка телефона, допуск), журнал с фильтрами в URL и CSV, смены (план/факт), аналитика с «как посчитано», помощник, настройки порогов |

Сценарий на двух устройствах: админка на ноутбуке → новый сотрудник → телефон сканирует инвайт → на ноутбуке открыть киоск → показать QR с телефона в камеру.

## Как устроено
- Vite + React 19 + TypeScript strict + Tailwind 4 + motion (+ ogl для живого фона), FSD; HashRouter — работает на Pages без fallback.
- Стиль только из `src/shared/config/tokens.ts` → `npm run gen:tokens` → `src/app/styles/theme.css` (ADR-033 основного репо). Проверка архитектуры и литералов — `node scripts/fsd-check.mjs src`.
- «Сервер» — `src/shared/api/mock/server.ts`: решение о проходе принимается там, UI показывает то, что вернулось (как Д2 в продукте). Коды и тексты отказов — из `docs/API.md` основного репо.

### Упрощения песочницы (в продукте иначе)
- Нет общего сервера, поэтому публичный ключ телефона едет внутри QR, а киоск привязывает его при первом скане. В продукте ключ регистрируется при активации, и чужой ключ = `DEVICE_UNKNOWN`.
- Ссылка-инвайт несёт карточку сотрудника, чтобы телефон без сервера знал, кого привязывает.
- Биометрии нет: живость — по движению в кадре (фото без движения не пройдёт), совпадение лица — переключатель в демо-пульте.
- История на телефоне видна, только если киоск открыт в том же браузере.

## Помощник
Без настройки отвечает правилами по данным (кто на объекте, опоздания, отказы, часы, конкретный сотрудник). Кнопка «Модель» подключает любой OpenAI-совместимый API с tool calling (DeepSeek, Qwen, GLM, локальный Ollama): модель вызывает те же инструменты, цифры берутся только из них. Ключ хранится только в `localStorage` вашего браузера; для общего стенда нужен прокси на сервере, чтобы ключ не попадал в браузер.
